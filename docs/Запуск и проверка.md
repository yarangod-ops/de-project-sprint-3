# Запуск и проверка

## Airflow

Используется учебный тренажёр `project-sprint-3` с Python 3.8.10 и Airflow 2.3.0.

1. Скопировать всё содержимое `src/dags/` в папку DAG тренажёра, включая `godiyak_etl` и SQL.
2. Создать подключения и переменные из таблиц ниже.
3. Найти DAG `godiyak_sales_retention` и запустить вручную с датой инкремента.

| Connection ID | Тип | Настройки |
|---|---|---|
| `godiyak_postgres` | Postgres | Host, Schema — имя учебной БД, Login, Password, Port |
| `godiyak_practicum_api` | HTTP | Host: `https://d5dg1j9kt695d30blp03.apigw.yandexcloud.net`; Password: ключ из задания |

Внутри учебного контейнера порт PostgreSQL — `5432`. Для подключения с компьютера используется проброшенный порт, например `15432`.

| Variable | Значение |
|---|---|
| `godiyak_nickname` | `godiyak_yaroslav` |
| `godiyak_cohort` | Номер когорты для учебного API |

Значение когорты `1` в `.env.example` взято из примера урока. Перед запуском нужно указать номер своего потока. Для разных профилей nickname/cohort следует использовать отдельные учебные базы.

В DAG три задачи:

```text
migrate_schema → prepare_report → load_increment
```

DAG создаётся на паузе. Пример конфигурации ручного запуска:

```json
{"business_date": "2026-10-18"}
```

Нужно выбрать доступную дату инкремента после дат начального отчёта. Если `business_date` не указана, используется Airflow `ds`. Для исправления дня нужно повторить запуск с той же датой.

## Проверка данных

Продажи и возвраты:

```sql
SELECT status, count(*) AS operations,
       sum(quantity) AS quantity, sum(payment_amount) AS revenue
FROM mart.f_sales
GROUP BY status;

SELECT count(*) AS bad_refunds
FROM mart.f_sales
WHERE status = 'refunded'
  AND (payment_amount > 0 OR quantity > 0);
```

У возвратов сумма и количество отрицательные. `bad_refunds` должен равняться нулю.

Недельная витрина:

```sql
SELECT * FROM mart.f_customer_retention ORDER BY week_start, item_id;

SELECT week_start, item_id, count(*)
FROM mart.f_customer_retention
GROUP BY week_start, item_id
HAVING count(*) > 1;
```

Во втором запросе не должно быть строк. В `period_name` должно быть `weekly`.

Для проверки повторного запуска нужно сохранить количество строк, общую выручку и строки retention, повторить загрузку той же даты и сравнить. Если исходные данные не менялись, результаты должны совпасть. Количество записей в журнале загрузок при этом увеличится.

```sql
SELECT count(*), sum(payment_amount) FROM mart.f_sales;

SELECT date_id, source_uniq_id, status, count(*)
FROM mart.f_sales
WHERE source_uniq_id IS NOT NULL
GROUP BY date_id, source_uniq_id, status
HAVING count(*) > 1;
```

Последний запрос должен вернуть пустой результат.

## Тесты

Команды выполняются из корня проекта. Для полного набора нужны Docker и зависимость из `requirements.txt`, установленная в используемом окружении Python.

```bash
python3 scripts/test_project.py --unit-only
python3 scripts/test_project.py
```

Первый вариант проверяет Python-код без Docker. Второй дополнительно проверяет SQL в отдельной временной PostgreSQL и удаляет тестовый контейнер после завершения. Учебная база для этих тестов не используется.

## Запуск через Python

В окружении Python 3.8+ установить зависимость и подготовить настройки:

```bash
python3 -m pip install -r requirements.txt
cp .env.example .env
```

Заполнить `.env`: ключ API, номер когорты и параметры учебной БД. Затем выполнить:

```bash
set -a
source .env
set +a
python3 scripts/run_pipeline.py --bootstrap-only
python3 scripts/run_pipeline.py --date 2026-10-18
```

Первая команда загружает начальный отчёт, вторая — выбранный день. Дату нужно заменить на доступную в API. Файл `.env` с паролями и ключом не добавляется в Git.
